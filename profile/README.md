<h2>一、带宽的三种标法</h2>
<p>独享带宽指这条线路的资源只给你用；共享带宽是同批用户分一条上行；不限流量则配一个速率上限。</p>
<p>三种写法在页面上很像，实际可用速度差得远，晚高峰同时测一次就能看出区别。</p>
<p>问报价时直接把口径问出来，写进订单，比事后争论有用。</p>

<h2>二、上行才是瓶颈</h2>
<p>家宽线路的下行通常远大于上行，而代理转发消耗的主要是上行，瓶颈几乎总在这一侧。</p>
<p>标称五百兆下行的套餐，上行可能只有二十兆，跑几个视频回传就满了。</p>
<p>选套餐时先问上行数值，问不到就自己上传文件实测，比看下行数字靠谱。</p>

<h2>三、并发与连接数怎么估</h2>
<p>并发不是设备数，而是同一时刻有数据传输的会话数，浏览器一个页面就能开出几十个连接。</p>
<p>按峰值并发乘以单会话的平均占用来估，再留三成余量，估太紧跑起来就卡。</p>
<p>长连接比短连接更吃资源，挂机类业务要按连接数而不是请求数来算。</p>
<h3>加密与转发开销</h3>
<p>加解密吃CPU，转发吃内存，两者都紧张时会表现为速度上不去但带宽没跑满。</p>
<h2>四、硬件配置的最低线</h2>
<p>十来个并发、只做转发的小机器，两核两G就够，瓶颈在线路不在硬件。</p>
<p>五十个并发以上建议四核四G起，同时把连接跟踪表调大，否则容易丢包。</p>
<p>上百并发要考虑网卡与中断分配，单核跑满会让延迟抖动明显。</p>
<p>硬盘不用配太大，系统和日志占几十G就够，同样的预算优先加到内存上。</p>
<p>内存不足时系统会频繁回收连接，表现出来像是线路抖动，实际是机器扛不住。</p>

<h3>监控比参数可靠</h3>
<p>装个简单的流量与负载监控，跑一周就知道瓶颈在带宽、CPU还是内存。</p>
<h2>五、按业务选型</h2>
<p>只做后台操作和网页访问的，中等带宽加低配硬件即可，钱花在地址质量上更值。</p>
<p>做视频或直播回传的，先把上行拉满，再看CPU是否够解封装，硬件次之。</p>
<p>多账号并行的，按账号数配带宽，按总连接数配内存，两端都留余量。</p>
<p>并发数会随业务增长，选配时按半年的预期买，不要只按当月数据卡着线。</p>
<h3>余量留给最紧的一项</h3>
<p>带宽和内存都留余量最稳，预算有限时优先保带宽，内存不够还能加。</p>
<h2>六、超配和欠配的代价</h2>
<p>超配的代价是月费浪费，带宽常年跑不到三成，属于花了钱没用上。</p>
<p>欠配的代价更隐蔽，表现为偶发卡顿和断线，排查半天才发现是资源打满。</p>
<p>合理做法是先按估算配，跑两周看监控曲线，再按实际峰值调整一档。</p>
<p>每个季度复核一次，业务结构变了，原来的档位往往已经不再合适。</p>
<h2>常见问答</h2>
<h3>带宽越大越好吗？</h3>
<p>答：不是。超过实际峰值就是浪费，关键看上行和稳定性，以及是否独享。</p>
<h3>家宽线路能跑满标称带宽吗？</h3>
<p>答：多数跑不满，实际能到标称的六到八成，共享线路在高峰更低，需实测。</p>
<h3>硬件差点会影响速度吗？</h3>
<p>答：会。CPU或连接跟踪表打满时，带宽没跑满也会卡，先看监控再判断。</p>
<h3>怎么知道该升带宽还是升配置？</h3>
<p>答：看监控：带宽利用率高就升带宽，CPU或内存高就升配置，两者都高就一起升。</p>
